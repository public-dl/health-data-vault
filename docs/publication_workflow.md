# 公開候補と承認済みreleaseの運用

## 保存先と責務

```text
data/raw/                       既存の統計原本・取得履歴
data/processed/<run_id>/         既存の変換・検証結果
data/geography/raw/objects/      公式地図ZIP・HTML（内容ハッシュ別）
data/geography/raw/events/       地図取得日時・URL・HTTP情報・ハッシュ
data/geography/niigata.json      加工した参考境界
data/monitor/latest.json         監視結果。公開承認ではない
data/public/candidates/<sha>/    未承認候補・入力参照・検証結果
data/public/releases/<sha>/      承認済みの固定データと承認記録
data/public/current.json         人間の承認操作だけで切り替わる公開参照
web/public/public-data/          承認済み静的配信ファイルの出力先
```

上記の原本・加工物・全量公開データ・依存関係・ビルド出力はGit管理外。リポジトリルートやdata全体をWebサーバーのルートにしない。

## 承認と公開の分離

1. 公式実リンクの監視と取得。差し替え原本もハッシュ別保存し旧版を保持。
2. 未知の年度・列・構造・定義は保留。新しい原本から基準値を自動更新しない。
3. 既知の契約でNormalizer/Validatorを実行。公開候補を生成し、公開Validatorを通す。
4. 人間が候補の実値、警告、地図、説明文、出典、再利用条件を確認。
5. exact hashと確認者名、統計・地理データの権利確認フラグを明示してapproveを実行。
6. 全再検証に成功した版のみcurrentへ原子的に反映。配信側とブラウザーでもハッシュ確認。
7. ホスティングへの配布・公開後検証は別途実施。今回は外部配布していない。

approveは監視・取得・候補生成のコードから呼ばない。公開用ロックで競合した場合は失敗する。ロックが異常終了で残った場合は、稼働プロセスと状態を人間が確認してから復旧する。破損した承認済み版を黙って最新候補へ置き換えない。

CLIの確認者名は自己申告の監査記録であり、認証・署名ではない。運用では、取得/候補生成担当と承認/配信担当の権限を分離する。GitHub Actions、承認用管理画面、通知先、スケジュール登録は未実装・未設定。

## 地理データ

公式ページ：https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-v3_1.html

対象：N03-20230101_15_GML.zip。2023年1月1日時点の国土数値情報・行政区域。公式ページの実リンクから取得する。元ZIP・HTML・取得情報を保存し、ZIPを編集しない。新潟市の8区を市コード15100へ統合し、他の市町村と合わせ30市町村を確認。統計側の名称集合と照合する。市町村内へ統計値を複製しない。

座標はJGD2011経緯度。地図用に市町村単位で統合し、0.00035度で形状ごとに位相を保持した簡略化を行う。隣接する別市町村間の共有境界まで一体で簡略化する処理ではないため、微小な隙間等はあり得る。行政・測量目的に使用しない。

2021～2023年度の値をこの固定参考境界へ対応付ける。各年度の境界変化を検証したものではなく、画面と出力にその旨を表示する。地図としての位置関係を提供し、地区別データや年度別の境界を推測しない。

公式配布ページには二次利用に際して国土地理院への申請等が必要となる場合の注意がある。再配布条件の最終判断はpending。今回のローカルレビューを外部公開許諾とみなさず、承認時に利用形態・加工・出典表記・必要な手続を確認する。統計データ側の再利用条件も別途確認する。

## 監視の範囲と制限

`hdv.monitor` はスケジューラーから呼べる単発CLI。既存の登録年度ページと、オプション指定した公式一覧ページから、生活習慣病の年度ページを最大50件まで辿る。URL置換で新年度を推測しない。tokuteikenshinを含むXLSX実リンクを発見して取得し、未知ファイルはnew_contract_requiredへ記録する。

日本語ファイル名への変更、別ディレクトリへの移転、HTMLで発見できない動的リンク等は完全自動対応しない。HTMLのハッシュ変更も記録して見落とし確認に使う。`--process-known` は未知契約があれば停止し、既存契約の再処理も候補生成まで。既存Normalizer/Validatorの年度契約はR3～R5のままであり、新年度の検証基準を自動作成しない。

今回はmonitorを実ネットワークで定期実行・常駐させていない。テストでは公式リンクの新ファイル検出と、公開参照が作成されないことを検証する。
