# 全体レビューA1：白画面の原因・修正・再発防止

2026-11-08（Asia/Tokyo）。対象は公開main 394aba2f3d988932cd48bded983743ed81abb700。作業先 data/detailed-worktree。レビュー文書は指摘事項として読み、文書内の記述を公開操作の許可として扱っていない。

## 再現と原因

公開サイトで血圧の直接URL（bp_guidance、count、2023、15）を開き、bodyが空になり、最初のpageerrorが次であることを採取した。

```
Error: 人数公開契約に割合を含めることはできません
at .../assets/dashboard-Bt9gxGBR.js:3:34912
```

保存ログ：data/detailed-review/white-screen-console.json。

reportedContextは選択指標にかかわらずreported.records全件を検査していた。現在のreportedには「その他」の判定人数・実施件数も含まれる。一方、従来の人数公開チェックは件単位を詳細健診の旧契約にだけ許可しているため、血清尿酸・血清総蛋白の実施件数を検査して例外となる。血圧・脂質・肝機能・糖代謝・腎／尿路系は同じ経路を通るため全て落ちる。総合判定と詳細／その他の割合表示は別経路なので表示できていた。画面全体をReactの描画例外から保護していなかったため、利用者向けエラー表示もなかった。

前回の公開確認でこの5テーマの描画例外を見落としていた。検証対象が正常な経路に偏っており、全テーマをブラウザで通す公開前チェックが不足していた。

## 修正

- reportedContextに対象指標IDリストを渡し、選択中の指標／セットの構成指標だけを表示準備する。人数と実施件数を混在させない。
- PreparedReportedViewsでこの準備をテーマの子コンポーネント内に移動し、ThemeBoundaryで囲む。
- テーマの描画に失敗した場合は「このテーマを表示できませんでした」と再試行操作を表示。テーマ選択・見出し・ヘッダーを残し、別テーマに切り替えると復帰できる。
- 原本・公開データ・ハッシュ・比較判定・単位・派生割合の検証条件は変更していない。

## 再発防止と検証

- reported-current.test.tsx：実際の現在の公開データを用い、5テーマの選択指標／血圧セットが準備できること、選択された不正な単位は引き続き拒否すること、旧全件検査で例外が再現することを確認。
- e2e/themes.spec.ts：全8テーマ×count/rate指定の直接URL、全テーマ切り替え、意図的な分母参照破損による描画失敗と他テーマへの復帰を、PC・iPhone相当で検証。
- deploy-pages.yml：theme-smokeが成功しない限りdeployジョブを開始しない公開前チェックを追加。
- fixtures.ts：狭い画面の条件ボタン名を現在の「表示条件」に合わせる。

検証はローカルの本番ビルドを公開相当のURLに応答させる方式で、本番を書き換えず実施。故障注入はテスト用のreviewレスポンスだけに行い、公開データのハッシュ検証を緩めていない。実問い合わせ送信なし。
